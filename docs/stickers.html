Build sticker packs for DarkPurpleOF's Website

A complete reference for the .dpfstickers pack format: how a pack is structured, what every sticker requires, how the built-in Sticker Pack Creator builds and imports packs, and how a finished pack gets shared.

01 How sticker packs work

A sticker pack is a single JSON file, exported with a .dpfstickers extension, that bundles pack metadata together with a list of individual stickers. It's built entirely client-side by the Sticker Pack Creator — no server upload is required just to create one.

At a high level, three things happen when you build a pack:

  1. You fill in the pack's identity — a Pack ID, a display Name, an Author, and an optional Description (up to 500 characters).
  2. You add stickers one at a time by pasting an https:// image URL. Each image is checked as you add it, and again in the gallery, against the recommended sticker dimensions.
  3. Once every sticker has a unique, non-empty ID and at least two stickers are present, Export to Sticker Pack unlocks and downloads a single <packId>.dpfstickers file to your device.
Nothing is uploaded until you export
The tool builds your pack entirely in memory in the browser. Nothing is written anywhere until you press Export, at which point a single .dpfstickers file is generated and downloaded — there's no draft saved server-side unless you do that yourself.

02 .dpfstickers format

Under the hood, a .dpfstickers file is just formatted JSON — readable, diffable, and easy to hand-edit or generate with a script if you'd rather not use the Creator's UI.

json · example.dpfstickers
{
  "packId": "sunday-mood",
  "name": "Sunday Mood",
  "description": "A small set of lazy weekend faces.",
  "author": "you@example.com",
  "date": "2026-07-31T12:00:00.000Z",
  "stickers": [
    { "id": "coffee", "name": "Coffee", "resource": "https://example.com/coffee.png" },
    { "id": "nap", "name": "Nap", "resource": "https://example.com/nap.png" }
  ]
}

date is written automatically at export time as an ISO 8601 timestamp — you never set it by hand. Every other top-level field comes directly from the Creator's form.

resource, not url
The exported JSON key for each sticker's image is resource — different from the internal url field the tool uses in memory while you're editing. If you're hand-writing or generating a .dpfstickers file, make sure every sticker entry uses resource.

03 Sticker requirements

Every image you add is checked against the same rules the app enforces once a pack is actually installed and displayed.

  • Count: a pack needs at least 2 stickers to export, and the Creator stops accepting new ones at 50.
  • Dimensions: images are added at up to 250×250 — anything larger is rejected outright at add time. Once in the gallery, anything below 200×200 or above 255×255 is flagged so you can swap it before exporting.
  • Source: every image is added by https:// URL only — there's no local file upload, so the URL must stay reachable for the sticker to keep working after import.
  • IDs: every sticker needs its own non-empty, unique id. Duplicate or missing IDs are called out per-sticker and block export until fixed.
Stickers display at a fixed size in the app
Images outside the 200–255px sweet spot may be cropped, scaled unpredictably, or fail to show once the pack is actually used. Aim for square, ~250×250 images for the safest result.

04 Creating a pack

The whole flow lives on one page — the Sticker Tool — with no separate submit step; the finished file downloads straight to your device.

  1. Open the Sticker Tool and fill in Pack ID, Pack Name, and Pack Author — these three fields lock once you import an existing pack, but stay editable while building a new one.
  2. Add a short Description if you want one (optional, 500 characters max).
  3. Click the + card to open the image dialog, paste an https:// image URL, and confirm — the sticker is added to the gallery with a live dimension check.
  4. Give every sticker a unique ID and, optionally, a display Name. Click a sticker's image again to swap its URL, or use the delete icon to remove it.
  5. Once you have at least 2 valid, uniquely-IDed stickers, Export to Sticker Pack unlocks — click it to download <packId>.dpfstickers.

05 Importing & editing

Use Import from Pack to load a .dpfstickers file back into the tool for editing.

  • The file must contain packId, name, author, and stickers, or the import is rejected with an "Invalid file format" message.
  • Once imported, Pack ID, Pack Name, and Pack Author are locked — you're editing the sticker set and description of an existing pack, not renaming it.
  • Every sticker from the file is loaded into the gallery with its stored id, name, and resource URL, ready to be edited or deleted like any other sticker.
Re-export overwrites the whole file
There's no partial-update mode — editing an imported pack and exporting again produces a brand-new <packId>.dpfstickers containing the full, current sticker set.

06 Field reference

Every field written into an exported .dpfstickers file, top to bottom.

FieldTypeDescription
packIdstringUnique identifier for the pack. Becomes the exported file's name: <packId>.dpfstickers.
namestringDisplay name shown wherever the pack is listed.
descriptionstringOptional summary, up to 500 characters.
authorstringAuthor identifier entered in the form — free text, not validated against an account.
datestring (ISO 8601)Export timestamp, generated automatically — not user-editable.
stickersarrayList of sticker objects, 2–50 entries, each described below.
stickers[].idstringUnique, non-empty ID for the sticker within this pack. Required to export.
stickers[].namestringOptional display name for the individual sticker.
stickers[].resourcestring (URL)https:// URL the sticker image is loaded from.

07 Validation rules

The Export button only unlocks once every rule below passes — the tool checks continuously as you edit, not just at export time.

RuleEnforced when
At least 2 stickers in the packOn every add / remove
Every sticker has a non-empty idOn every edit
No two stickers share the same idOn every edit
Each image is 250×250 or smallerWhen adding or replacing an image
Image URL starts with https://When adding or replacing an image
Imported file has packId, name, author, stickersOn import
Size warnings don't block export
The 200–255px dimension check only warns — a pack with a too-small or too-big sticker can still export. Only missing/duplicate IDs and having fewer than 2 stickers actually block the Export button.

08 Exporting & file naming

Export to Sticker Pack serializes the current pack to JSON, wraps it as an application/json blob, and triggers a browser download named after the pack: <packId>.dpfstickers.

  • The filename is always <packId>.dpfstickers — pick a Pack ID you're comfortable seeing as the literal filename.
  • The generated JSON is pretty-printed (2-space indent), so it's easy to open, diff, or hand-edit afterward.
  • Because everything happens in the browser, exporting doesn't require you to be signed in or connected — only loading a language preference tied to your account does.

Sharing & distribution

A .dpfstickers file is a self-contained artifact — share it however you'd share any small file.

  • Send the file directly (chat, email, file share) and the recipient can load it with Import from Pack to inspect or continue editing it.
  • For store or index distribution, the same file is what you'd submit — validate it against the field reference and validation rules above before sharing it widely.
  • Because every image is referenced by https:// URL rather than embedded, a pack's stickers stay live only as long as those URLs do — use stable, long-lived hosting for anything you plan to distribute widely.
